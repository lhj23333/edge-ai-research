核心设计原则：让确定性情报雷达与深度研究引擎各司其职

重构前的核心矛盾在于职责混杂——系统试图让昂贵的 LangGraph 高思考代理每天通过通用 Search API 充当“新闻采集器”，既无法约束搜索引擎返回历史旧文，又难以把多方转载合并为单一事件。重构后的最终形态将系统拆分为完全解耦的两大引擎，通过统一的 documents 与 events 数据底座衔接。

上游情报漏斗负责“广度、时效、去重与降噪”：它以确定性 HTTP 抓取为入口，按时间水位线拦截存量旧闻，通过外置行业提示词与 T1/T1.5/T2 分级双评筛出高价值信号，再用本地向量完成跨源事件聚簇与规则化日报编排。下游深度研究引擎负责“深度、溯源、对比与认知沉淀”：它只在用户主动提问、发起定向核验或高分 T1 重大发布触发时启动，直接读取本地已归档的一手原文片段，产出带原子证据链的专题判断、认知地图与产品横向对比。

完整功能版图：前台研究工作台与后台信源运营台

重构不会推倒重写你已经打磨好的前台交互（HTMX + Jinja2 + Ctrl-K 命令面板 + 本机私有安全边界），而是将“信源采集、漏斗诊断、模型路由”补齐为独立的后台运营域，并让前台的“今日简报”“行业动态”“事件详情”全面切换到高质量的聚簇事件数据。

上游情报漏斗：从根本上杜绝旧闻刷屏与转载污染

借鉴 AIHOT 信源体系 与 精选校准机制，上游流水线将端侧 AI 加速器的行业知识外置在 industry/ 目录（sources.json、selection.json、prompts/），所有原始条目在进入前台事件表之前必须通过四层确定性过滤与模型漏斗。

四类受控信源与分级

内置 rss、web_list（静态 HTML CSS 选择器 + 详情页补全）、json_list（直连 GitHub Releases / 官网 API）和 external（本地脚本推送接口），默认零第三方付费采集依赖。信源划分为 T1 官方一手（芯片厂商官网博客/发布页/GitHub）、T1.5 官方与准官方账号、T2 垂直媒体与个人，并支持通过 publisherUrlPrefixes 将聚合站转帖自动归回 T1 官方名下。

三道硬性时间与去重闸门

首先通过 canonical_url 与 source_aliases 拦截重复链接；其次严格执行 published_after 监控起点与首次导入限流（默认前 30 条且 12 个月内，标记为 is_backfill=1）；最后执行 48 小时规则——首次发现时原文发布已超 48 小时直接标为 gated_archive 归档不进今日动态，缺少可信发布日期的条目先标 pending_date 待详情页补齐日期后再判新旧。

预筛 + 独立双评 + 校准闭环

新条目先凭标题与摘要过一遍低成本 prefilter，挡掉招聘、展会通稿和纯营销软文；过审后才用 Trafilatura 抓取全文存入 documents，随后按同一份 score.md 标准独立打两次分取均值，对照信源分级门槛（如默认 T1 60 / T1.5 65 / T2 76，开发者高频源可按类别抬高门槛）决定入选。所有评分与理由留痕，定期用标注样本集校准。

基于本地 BGE-M3 的跨源事件聚簇与一手归属算法

同一款端侧 NPU 芯片或 SDK 发布，官网发一篇公告、GitHub 发一个 Release、海外媒体转五篇、国内媒体编译十篇——在你的系统里，读者只应该在今日简报看到一个统一事件，点进去能看到所有来源的时间线与一手依据。你现有的 knowledge.py 已经部署了本地 BAAI/bge-m3 与 sqlite-vec，这让跨源聚簇无需额外采购向量 API。

  1. 本地向量粗召回（0 API 成本）：条目通过双评并生成中文标题与摘要后，用本地 BGE-M3 计算 1024 维向量，在 data/search.sqlite3 的 event_vectors 中仅检索近 14 天内活跃事件的 Top-5 相似候选。
  2. 相似度短路优化：若 Top-1 余弦相似度低于下限阈值（默认 0.62），说明近两周无相近事件，直接创建新事件并写入向量表，直接省去聚簇模型调用。
  3. 三态关系判定与存疑复核：高于阈值时，将新条目与候选事件交给 cluster 路由（快模型，关闭思考），输出 same_event（同一件事）、follow_up（同一事件的后续进展）或 new_event（独立新事件），并给出置信度 high / uncertain。借鉴 AIHOT 的复核机制，仅当置信度为 uncertain 时，写入前交由 cluster_review（可配置不同厂商模型）二次复核。
  4. 一手代表报道优先与抗刷屏热度：归入同一事件后，按 T1 > T1.5（归属该厂商实体）> T2 自动选举 representative_document_id；事件热度按 48 小时内独立信源数计算（每 24 小时衰减一半），同一家媒体连发多篇或重复抓取只计 1 次，人工修正过的归属锁定不被后续自动覆盖。

上游聚簇解决“不重复看同一条新闻”，下游核验解决“不把媒体转述当成芯片实测数据”。

双引擎协同边界：聚簇层产出事件与多源时间线，证据层继续坚守原网页核验与条件拆解

下游深度研究联动：保留并放大你原有的核心护城河

相比纯资讯聚合站，你现有仓库最稀缺的价值是可审计的领域知识沉淀。重构后，下游所有研究能力全部保留，并在输入质量上获得质的提升：

事件直通 LangGraph 深度核验

每个聚簇事件页新增“深度研究此事件”操作：点击后自动把该事件下已抓取的 T1 官方原文、GitHub Release Notes 与多方媒体文档切片注入 LangGraph 初始上下文，让模型先读本地一手资料、再针对缺失的功耗/精度/SDK 条件做精准补搜，大幅减少无效搜索轮次。

四级证据与口径边界不妥协

继续严格区分“公开披露”“厂商宣称”“分析判断”“待核实”；所有原子说法（claims）强制关联原文切片与版本号；产品对比（/compare）在测试批量、量化精度、功耗条件缺失或不一致时继续拒绝生成误导性排名。

认知地图与专题判断演进

当某厂商连续出现高分事件或 T1 重大版本更新时，系统可在事件页提示“刷新相关专题判断”，支持零联网纯基于本地新入库证据重整“行业竞争”与“部署决策”两项综合判断，并完整保留修订前后版本与反对证据。

个人批注与反馈闭环

个人批注（annotations）保持独立存储与版本记录，仅在发起单次研究时显式勾选才发送给模型，永远不污染公开证据库；同时保留操作幂等与断点续传（research_operations），防止异常重试造成重复扣费。

快慢模型分层路由与成本可控性设计

借鉴 AIHOT 的省钱实践（每步独立换模型、关闭非必要思考模式、按步骤统计 token、设预算熔断），将 researcher/config.py 从单一 active_profile 升级为 7 个具名步骤路由 model_routes，让 90% 以上的日常调用落在低价非思考通道。

技术栈、模块布局与完整数据模型（007_source_funnel.sql）

整套重构保持纯 Python 3.10+、FastAPI、SQLite（WAL 模式）、sqlite-vec 与 systemd --user 单机双进程（researcher-web + researcher-worker）运行，不引入 PostgreSQL 或 Docker 额外运维负担，同时完全兼容现有 researcher backup / restore 一致性备份体系。

核心运行保障与运维约束

  • 手动深研永远优先：保留 worker.py 的 YieldResearch 让出机制；后台信源采集与漏斗打分作为低优先级常驻协程运行，一旦用户发起手动深度研究或定向提问，立即优先调度手动任务。
  • 安全抓取边界：沿用 knowledge.py 的 public_url 校验，默认禁止抓取内网及云元数据地址，仅允许在环境变量中为自建 RSSHub 等内网订阅源设置白名单主机名；web_list 与 rss 全面启用 ETag / Last-Modified 条件请求减少带宽消耗。
  • 信源健康自愈与自适应频率：参考 AIHOT 抓取频率策略，每日定时按近 7 天产出量动态调节抓取间隔（高频源 15–30 分钟，低频官网 60–180 分钟）；按近 90 天产出日的中位间隔判断断更（超 4 倍中位间隔标红），避免低频官方博客误报故障。
  • 零回归测试与平滑迁移：新增独立测试套件覆盖时间闸门、分级双评、BGE-M3 聚簇短路与快慢模型路由；所有旧事件、证据、认知地图与批注通过 007_source_funnel.sql 无损保留。
